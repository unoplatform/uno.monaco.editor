# fn-5-comprehensive-documentation-overhaul.6 Add XML documentation to generated Monaco types

## Description
Add XML documentation to the generated Monaco type files in `MonacoEditorComponent/Monaco/`. This task runs after fn-4 (type generation pipeline) completes, so the type emitter output will be stable. Details for this task should be refined once fn-4.5 (emitter) output is finalized.

**Size:** M (40+ files but most are small enums/interfaces needing brief docs)
**Files:** `MonacoEditorComponent/Monaco/Editor/*.cs`, `MonacoEditorComponent/Monaco/Languages/*.cs`, `MonacoEditorComponent/Monaco/Helpers/*.cs`, `MonacoEditorComponent/Monaco/*.cs`

## Approach

Two potential strategies (decide after fn-4.5 completes):

**Strategy A — Emitter generates XML docs**: Modify the type emitter (fn-4.5 output) to emit XML docs derived from TypeScript JSDoc comments in the Monaco `.d.ts` file. This keeps docs in sync automatically.

**Strategy B — Hand-written XML docs**: Add XML docs manually to the emitter output. Requires a post-processing step or convention to preserve docs across regeneration.

**Regardless of strategy:**
- Core types needing thorough docs: `Position`, `Range`, `Selection`, `IPosition`, `IRange`, `Uri`, `IMarkdownString`
- Editor types: `StandaloneEditorConstructionOptions` (84 public members — largest single file), `IEditorOptions` (422 comment lines), `IModelDeltaDecoration`, `IModelDecorationOptions`, `Marker`, `MarkerData`, `FindMatch`, `ContextKey`
- Language types: `CompletionItem`, `CompletionList`, `CodeAction`, `Hover`, `TextEdit`, `WorkspaceEdit`, `Command`
- Provider interfaces: `HoverProvider`, `CompletionItemProvider`, `CodeActionProvider`, `CodeLensProvider`, `DocumentColorProvider`
- Enums (~35+): `MarkerSeverity`, `MarkerTag`, `SelectionDirection`, `CompletionItemKind`, `CursorBlinking`, `WordWrap`, `AutoIndent`, etc.
- Use `<see href="..."/>` to cross-reference upstream Monaco TypeDoc API for each type
- Mark generated files with `// <auto-generated />` header if not already present
