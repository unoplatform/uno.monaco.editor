# fn-2-type-generation-pipeline-and.7 Modernize type generation pipeline for STJ output

## Description
Replace the dead TypedocConverter-based type generation pipeline with a post-processing approach that emits STJ-attributed C# from Monaco TypeScript definitions. Output goes to an isolated directory. Also completes repo-wide Newtonsoft cleanup.

**Size:** M
**Files:** GenerateMonacoTypings/* (rewrite), GenerateMonacoTypings/README.md, GenerateMonacoTypings/postprocess-stj.ps1 (new)

## Approach — Option B: Post-processing

The chosen approach is **post-processing**: run TypedocConverter as-is (it still works for basic generation), then apply a deterministic post-processing step to transform Newtonsoft attributes to STJ attributes.

**Step 1: Update Monaco version and ensure a working generation path**
- Update `GenerateMonacoTypings/package.json` to reference `monaco-editor@0.54.0` (match vendored runtime)
- Verify TypedocConverter can still parse the newer typings (may need TypeDoc version update)
- If TypedocConverter fails on 0.54.0: the post-processing script must ALSO work as a standalone tool that transforms existing `.cs` files in-place (i.e., can be run against `MonacoEditorComponent/Monaco/` without TypedocConverter). This ensures a working path regardless of TypedocConverter status.
- **Requirement**: At least one of these must succeed: (a) full pipeline TypedocConverter+postprocess on 0.54.0, OR (b) standalone postprocess on existing files. Both must produce compilable STJ output.

**Step 2: Build post-processing script** (`postprocess-stj.ps1`):
- Transform `[JsonProperty("name")]` -> `[JsonPropertyName("name")]` or remove if CamelCase covers it
- Transform `[JsonProperty("name", NullValueHandling = NullValueHandling.Ignore)]` -> `[JsonPropertyName("name")]` (global default handles null)
- Transform `[JsonConverter(typeof(XConverter))]` -> `[JsonConverter(typeof(JsonStringEnumConverter<X>))]` for string-backed enums
- Replace `using Newtonsoft.Json` -> `using System.Text.Json.Serialization`
- Add `// <auto-generated />` header to all output files
- Enable nullable reference types (`#nullable enable` or project-level)
- Output to `GenerateMonacoTypings/output/` (isolated, NOT into MonacoEditorComponent/Monaco/)

**Step 3: Define overwrite protection**
- Hand-tuned files (e.g., `StandaloneEditorConstructionOptions` with `INotifyPropertyChanged` + dictionary backing) listed in a `.generator-ignore` manifest
- Post-processor skips files in the ignore list
- Generated output in `GenerateMonacoTypings/output/` can be manually diff'd and selectively merged

**Step 4: Repo-wide Newtonsoft cleanup**
- Remove any remaining Newtonsoft references in GenerateMonacoTypings/ scripts or output
- Verify: `grep -r "Newtonsoft" . --include="*.cs" --include="*.csproj" --include="*.ps1"` returns zero results repo-wide

**Step 5: Update documentation**
- Rewrite `GenerateMonacoTypings/README.md` with new pipeline docs
- Document the post-processing step, output directory, ignore list, and merge workflow

## Key context

- TypedocConverter (hez2010/TypedocConverter) last updated 2023-03-29. Supports TS 3.9-4.2. May fail on Monaco 0.54.0 which uses TS 5.x features — the post-processor is designed to be resilient to this.
- The version gap (0.21.3 -> 0.54.0) means regeneration will produce a different type surface. Full regeneration is a follow-up outside this epic.
- `StandaloneEditorConstructionOptions` is heavily hand-tuned — must be in the `.generator-ignore` list.
- This task completes the repo-wide Newtonsoft cleanup that task 6 started (task 6 handles MonacoEditorComponent/, this task handles GenerateMonacoTypings/).
