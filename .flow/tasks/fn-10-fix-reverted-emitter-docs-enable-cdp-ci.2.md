# fn-10-fix-reverted-emitter-docs-enable-cdp-ci.2 Regenerate Monaco types with XML docs and re-enable CS1591

## Description
Re-run the full type generation pipeline after emitter edge cases are fixed, producing Monaco `.cs` files with XML documentation. Before regenerating, update the emitter to emit all types as `partial` so consumers can extend generated types in separate files. Then re-enable CS1591 warnings in `MonacoEditorComponent/Monaco/.editorconfig`. Update CHANGELOG.md with Unreleased entries for all fn-10 changes.

**Size:** M
**Files:** `tools/MonacoTypeEmitter/Emitter/CSharpEmitter.cs` (partial keyword), `MonacoEditorComponent/Monaco/**/*.cs` (generated), `MonacoEditorComponent/Monaco/.editorconfig`, `docs/generated-type-docs-strategy.md`, `CHANGELOG.md`, `tools/MonacoTypeEmitter.Tests/Snapshots/Verified/*.cs` (snapshot updates)

## Approach

### Pre-regeneration: add `partial` to emitter output
Before running the pipeline, update `CSharpEmitter.cs` to emit `partial` on all type declarations:
- L204: `public enum` → `public partial enum` (numeric enums)
- L270: `public enum` → `public partial enum` (string enum type aliases)
- L356: `public interface` → `public partial interface` (interfaces)

This is a 3-line change. All snapshot tests will need updating (run `dotnet test` with update mode or regenerate verified files). The regenerated Monaco `.cs` files will automatically pick up `partial`.

**Why `partial`:** Generated types should be extensible without modifying generated files. Consumers can add methods, implement additional interfaces, or add attributes in a separate partial file. This is standard .NET code-gen practice (EF, protobuf-net, source generators all emit partial types).

### Pipeline execution
- Run the type extractor: `npx tsx tools/monaco-type-extractor/src/index.ts -- node_modules/monaco-editor/monaco.d.ts -o tools/monaco-type-extractor/output/model.json`
- Run the emitter: `dotnet run --project tools/MonacoTypeEmitter -- --input tools/monaco-type-extractor/output/model.json --output MonacoEditorComponent/Monaco/`
- Verify generated files have `// <auto-generated />` headers, `<summary>` docs, `<remarks>` with TypeDoc URLs, enum member docs, and `partial` keyword

### Post-regeneration
- Change `Monaco/.editorconfig` CS1591 severity from `none` to `warning` (or remove the line) so builds enforce XML docs
- Build with `dotnet build MonacoEditorComponent.slnx` to verify compilation
- Update `docs/generated-type-docs-strategy.md`: mark acceptance criteria as complete; explicitly mark the known TypeDoc URL pattern drift (`editor.*` vs `editor_editor_api.*`) as **deferred** with a tracked follow-up TODO
- Update `CHANGELOG.md` Unreleased section with entries for: emitter edge-case fixes (from fn-10.1), partial type generation, XML doc regeneration, CS1591 re-enablement, Desktop CDP CI enablement (from fn-10.3), WSL2 profile (from fn-10.4), unified script invocation and WASM/desktop parity (from fn-10.6)
