# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

This is the first release under the **`Uno.Monaco.Editor`** package name (formerly `Monaco.Editor`).
It includes major architectural changes, a new platform target, and a complete serialization migration.

Monaco Editor version: **0.52.2** (declared `^0.52.2` in `package.json`; resolved version verified from `node_modules/monaco-editor/package.json` at release preparation time).

### Added

- **`DiffCodeEditor` control**: a two-sided comparison view over Monaco's diff editor, sibling to `CodeEditor`. Exposes `OriginalText` / `ModifiedText`, an optional per-side `OriginalLanguage`, `DiffOptions` (side-by-side or inline, whitespace handling, diff algorithm, collapsing of unchanged regions), `GoToDiffAsync` / `RevealFirstDiffAsync` navigation, a `DiffUpdated` event, and `GetLineChangesAsync()` for the computed hunks. Distinct from the built-in `diff` *language* below, which only syntax-highlights patch text. The modified (right) document is the editable one, and the inherited members act on it: selection, decorations, markers, options, cursor position, actions, and commands
- **`CodeEditorBase`**: the host, lifecycle, and bridge shared by `CodeEditor` and `DiffCodeEditor`. `CodeEditor` keeps `Text`; the diff control uses `OriginalText` / `ModifiedText` instead, so neither carries an overloaded name
- **Built-in `diff` language**: Monaco ships no diff grammar (VS Code's is a TextMate grammar from a built-in extension, and Monaco only supports Monarch), so the component now bundles and registers one. `CodeLanguage = "diff"` highlights unified/git, context, normal, and combined diffs; `.diff` and `.patch` resolve through `FileExtension` and `GetCodeLanguageFromExtension` on both WASM and desktop. Colors are inherited from the active built-in theme rather than redefining it
- **XML documentation on generated types**: enriched 71 generated Monaco C# files with `<summary>`, `<remarks>`, and per-member XML docs derived from upstream TypeScript JSDoc; added `// <auto-generated />` headers and `partial` keyword on all generated interfaces and classes
- **Emitter edge-case fixes**: handle `$`-prefixed properties, dotted identifiers, TypeScript type guard return syntax, void brand properties, and sealed class inheritance in the type emitter
- **Emitter `--update-only` mode**: new CLI flag restricts the emitter to only overwriting existing files, preventing creation of untracked types
- **CS1591 diagnostic re-enabled**: raised severity from `none` to `suggestion` in `Monaco/.editorconfig` to surface missing XML documentation
- **Unified `InvokeMethodAsync`**: single method invocation path on `ICodeEditorPresenter` for both WASM and Desktop platforms
- **Desktop Skia support**: desktop platform support on `net10.0` via runtime platform detection, WebView2-based presenter, and JSON-RPC bridge (Windows, macOS, Linux)
- **`ICodeEditorPresenter` abstraction**: pluggable presenter pattern replacing the monolithic WebView coupling; WASM and Desktop each have dedicated implementations
- **`EditorLifecycleState` state machine**: deterministic lifecycle management replacing ad-hoc boolean flags with a proper state machine
- **ESM module bundling**: migrated from AMD/global Monaco script loading to ES modules with esbuild, enabling tree-shaking and faster load times
- **Desktop JS bridge**: dual-mode communication layer (JSON-RPC over WebView2 `WebMessageReceived`) for invoking Monaco APIs from .NET on desktop targets
- **`RegisterTypeInfo` API**: replaces the obsoleted `AddAssemblyForTypeLookup` for registering custom types with the serialization layer
- **`MonacoJsonContext` source generator**: AOT-compatible `System.Text.Json` serialization context covering all Monaco API types
- **STJ contract tests**: comprehensive serialization round-trip tests validating JSON contract stability
- **Type generation pipeline**: new `ts-morph` extractor (`tools/monaco-type-extractor/`) and .NET CLI emitter (`tools/MonacoTypeEmitter/`) replacing the legacy `GenerateMonacoTypings` MSBuild target
- **Type emitter snapshot tests**: generator pipeline tests in `tools/MonacoTypeEmitter.Tests/` with snapshot verification
- **Integration test suite**: Playwright-based WASM tests and desktop CDP integration tests with xUnit v3
- **Code coverage collection**: merged coverage reporting across test projects in CI
- **CI modernization**: GitHub Actions with macOS ARM runners, .NET 10 SDK, updated action versions, and split build/test/coverage jobs
- **`FileExtension` property**: infer `CodeLanguage` from file extension automatically
- **ResizeObserver for WASM**: replaced `LayoutUpdated` resize handler with native `ResizeObserver` for better performance
- **PR reviewer guide**: structured review guide for the refactoring branch covering all four epics

### Fixed

- **WASM: the editor worker is now served**, which the diff editor requires. Monaco computes diffs through `EditorWorkerService`, and its fall-back-to-main-thread path only triggers when the `Worker` constructor throws; a 404 URL fails asynchronously, so the computation hung forever. `MonacoEnvironment` now overrides `getWorker` rather than `getWorkerUrl` (Monaco 0.52's ESM build constructs the latter with `type: 'module'`, but these bundles are IIFE) and resolves the flattened `workers.editor.worker.js` name that Uno.Wasm.Bootstrap actually deploys. Only the editor worker is embedded; the four language workers (~8.2 MB) remain out of the payload, so the component assembly grows from 5.20 MB to 5.55 MB rather than back to 13.68 MB. Verified on WASM and on Windows desktop; the switch to a classic worker on macOS/Linux desktop, which navigates `file://` rather than the virtual host, is unverified — a classic worker there is a cross-origin load whose constructor throws synchronously, which does trigger Monaco's main-thread fallback, so it should be no worse than the previous `type: 'module'` behavior
- **Duplicate editor initialization**: `CodeEditorLoaded` could run twice for a single bootstrap when the init-completion probe landed inside the window before the lifecycle state was updated, re-applying every initial property and potentially raising `EditorLoaded` twice. Guarded against re-entry
- **`INIT_COMPLETE` diagnostic marker** is emitted through `DiagnosticLog` instead of `Debug.WriteLine`, which is `[Conditional("DEBUG")]` and therefore absent from the Release builds the integration suite runs against. The marker is now qualified by control type

### Changed

- **Package rename**: NuGet package ID changed from `Monaco.Editor` to `Uno.Monaco.Editor`
- **Serialization**: migrated all JSON serialization from `Newtonsoft.Json` to `System.Text.Json` with AOT-compatible source generators
- **`CommandHandler` delegate**: now receives `System.Text.Json.JsonElement` instead of `Newtonsoft.Json.Linq.JObject`
- **Custom converters**: all domain-specific JSON converters rewritten for `System.Text.Json` (string enums use `JsonStringEnumMemberName`)
- **`ParentAccessor`**: redesigned for AOT-compatible serialization with `System.Text.Json`
- **TFM consolidation**: unified to `net10.0` with runtime platform detection replacing compile-time `#if` directives
- **Uno Platform upgrade**: updated to Uno 5+ / WinUI, targeting .NET 10
- **Monaco Editor upgrade**: updated from v0.21.3 to v0.52.2
- **CI pipeline**: migrated from Azure Pipelines to GitHub Actions with NuGet signing
- **Versioning**: switched to Nerdbank.GitVersioning
- **Build system**: migrated to `.slnx` solution format, modernized `Directory.Build.props`
- **Production JS bundles**: one-shot esbuild builds are now minified with no source maps (watch builds stay unminified with inline maps), cutting the bundled JavaScript from 46.7 MB to 12.8 MB; `--no-minify`, `--minify`, and `--sourcemap` override the defaults

### Deprecated

- **`AddAssemblyForTypeLookup`**: obsoleted in favor of `RegisterTypeInfo`
- **`LanguagesHelper`**: use `<EditorInstance>.Languages.*` instead (previously deprecated in v0.9)

### Removed

- **`Newtonsoft.Json` dependency**: the transitive NuGet dependency has been removed from the library
- **Legacy `GenerateMonacoTypings` MSBuild target**: replaced by the new `ts-morph` + .NET CLI emitter pipeline
- **AMD script loading**: replaced by ESM module bundling with esbuild
- **`build/` directory**: stale build artifacts directory removed
- **Worker bundles as WASM embedded resources**: the five Monaco language-worker bundles are no longer embedded for WebAssembly. Uno flattens `WasmScripts\workers\*.worker.js` to dot-joined names while `MonacoEnvironment.getWorkerUrl` resolves them under a `workers/` subdirectory, so they always 404 and Monaco fell back to main-thread language services — they were ~8.5 MB of unreachable payload. Desktop is unaffected

### Fixed

- **WASM: Monaco's stylesheet is now served**, so the editor is styled rather than falling back to browser defaults. `uno-monaco-helpers.css` was embedded under the `WasmScripts` logical name, which Uno.Wasm.Bootstrap extracts as *scripts*: the `.css` file was silently dropped, never deployed to `wwwroot/package_<hash>/` and never linked. Verified in Chromium against the built app -- `document.styleSheets` held only Uno's four sheets plus Monaco's runtime-injected theme rules, with no rule matching `.monaco-editor` at all. Monaco sets much of its layout inline, which masked the failure, but the codicon `@font-face` lives in this file: Monaco's icons rendered as tofu, action-bar lists kept their default bullets, and `.line-numbers` lost its absolute positioning and right alignment. The resource now carries a `WasmCSS` logical name, the prefix Uno deploys and `<link>`s. Desktop was never affected -- `editor.html` links the `DesktopContent` copy directly
- Fix `DirectoryNotFoundException` on desktop when the control is consumed from the NuGet package: `DesktopContent` is now probed at both `<output>/DesktopContent` and `<output>/MonacoEditorComponent/DesktopContent` (the layout `GenerateLibraryLayout` produces), and the probe requires `editor.html` rather than merely the directory
- Fix `automaticLayout` replacing buggy manual `window.resize` handling ([#27](https://github.com/unoplatform/uno.monaco.editor/pull/27))
- Fix redundant DOM Loading subscription affecting Playground ([#26](https://github.com/unoplatform/uno.monaco.editor/pull/26))
- Fix highlighting not working ([#25](https://github.com/unoplatform/uno.monaco.editor/pull/25))
- Fix Monaco not working with updated lifecycle in NPE ([#24](https://github.com/unoplatform/uno.monaco.editor/pull/24))
- Fix function names collision in `UpdateOptions` ([#21](https://github.com/unoplatform/uno.monaco.editor/pull/21))
- Fix editor launch compatibility with .NET 8
- Fix double desanitization in WASM `SetValue` path
- Fix `IMarkerData` round-trip serialization for AOT
- Fix initialization timing: apply initial property values on `CodeEditor` load ([#29](https://github.com/unoplatform/uno.monaco.editor/pull/29))
- Fix layout refresh during Monaco editor initialization
- Guard `CodeEditorLoaded` and fix sanitize value flow
- Guard presenter handlers against post-unload callbacks
- Gate lifecycle notifications on `CoreWebView2` readiness
- Single-owner `JsonRpc` initialization preventing orphaned instances

### Security

- Navigation allowlist enforces strict origin matching (scheme + exact host + port) to prevent subdomain and query-string bypass attacks
- WebView2 `Source` is deferred until after `EnsureCoreWebView2Async` completes to prevent allowlist bypass during initialization
- Inbound message queue uses `Channel.CreateBounded` to prevent DoS via memory exhaustion from untrusted sources

### Migration Guide

This release contains several breaking changes. Follow these steps to migrate from `Monaco.Editor` 2.0.0-dev.60 or earlier:

1. **Target framework**: Upgrade consuming projects to .NET 10 and Uno Platform 5+. The library now targets `net10.0` exclusively.

2. **Package reference**: Replace `Monaco.Editor` with `Uno.Monaco.Editor` in your project file.

3. **Newtonsoft.Json removal**: If your project relied on `Newtonsoft.Json` being provided transitively, add `<PackageReference Include="Newtonsoft.Json" />` to your project directly.

4. **CommandHandler callbacks**: Replace `JObject`/`JToken` usage with `JsonElement` and its accessor methods (`.GetProperty()`, `.GetString()`, etc.).

   ```csharp
   // Before (Newtonsoft)
   editor.AddCommandAsync(myCommand, (JObject args) => { ... });

   // After (System.Text.Json)
   editor.AddCommandAsync(myCommand, (JsonElement args) => { ... });
   ```

5. **Custom JSON converters**: Rewrite `Newtonsoft.Json.JsonConverter` subclasses as `System.Text.Json.Serialization.JsonConverter<T>` implementations.

6. **Type registration**: Replace `AddAssemblyForTypeLookup` calls with `RegisterTypeInfo`.

7. **Desktop target**: If targeting desktop, implement or use the provided `ICodeEditorPresenter` for WebView2 hosting. The `EditorLifecycleState` state machine governs initialization flow.
